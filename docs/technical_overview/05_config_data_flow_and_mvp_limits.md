## Конфигурация

### Настройки меню и звука

- В `Main Menu` и `Game Menu` добавлен экран `Settings` с вкладками `Graphics` и `Sound`; активная вкладка хранится в `MainMenuUiState`.
- В `src/ui/slider.rs` добавлен переиспользуемый компонент `slider` с настраиваемыми `min_value`, `max_value`, `step`, поддержкой клика/drag по треку и квантизацией по шагу.
- Для громкости музыки используется шкала `0..100` (UI/конфиг), а перед применением в BGM-runtime значение нормализуется в `0.0..1.0` (`value / 100.0` с clamp).
- Runtime-состояние звука хранится в `AudioSettingsState`: `saved_music_volume_percent` (последнее сохранённое) и `runtime_music_volume_percent` (текущее live-значение).
- Файл `config/settings.toml` читается на старте; при отсутствии файла или ошибке парса применяется fallback `50`.
- Сохранение в `config/settings.toml` выполняется только по кнопке `Save` на вкладке `Sound`.

### Фоновая музыка (BGM)

- Для фоновой музыки добавлен отдельный plugin `BgmPlugin` (`src/bgm/mod.rs`), подключаемый на уровне `app` и не завязанный на gameplay-системы симуляции; target-громкость берётся из `AudioSettingsState` в шкале `0.0..1.0`.
- Каталоги `assets/music/menu` и `assets/music/game` сканируются только один раз при запуске приложения; дальше runtime использует только уже собранные списки треков.
- `BgmPlugin` поддерживает два контекста (`Main Menu` и `игра/игровое меню`) и переключает их сразу при изменении `WorldLoadState.has_world` без ожидания завершения текущего файла.
- Воспроизведение работает как бесконечный цикл: `StartFadeIn -> Playing -> StartFadeOut -> InterTrackPause -> NextTrack`.
- Для обычной смены треков внутри одного контекста используются `fade-in 2.5s` и `fade-out 2.5s`; для переходов `menu <-> game` применяется более короткий fade `1s` в обе стороны.
- Выбор следующего файла в каждом контексте случайный и независимый: повторы одного и того же трека подряд допустимы.
- Если в каталоге контекста нет `.mp3`, plugin оставляет этот контекст в тишине и пишет warning в лог; fallback на другой контекст не выполняется.
- При target-громкости `0.0` BGM-планировщик полностью приостанавливается: активный трек останавливается, новые треки не запускаются (`phase = Suspended`).
- При возврате target-громкости выше `0.0` BGM-планировщик автоматически возобновляет обычный цикл `NextTrack -> fade-in -> play -> fade-out`.

Основные группы конфигов:
- `config/simulation.toml` для core/free-gas настроек движка;
- `src/plugins/default_plugin/config/pipe_runtime.toml` для pipe-runtime default plugin-а;
- `src/plugins/default_plugin/config/cell_types.toml`;
- `src/plugins/default_plugin/config/gases/*.toml`;
- `src/plugins/default_plugin/config/structures/*.toml`.

Назначение: вынести игровые и симуляционные параметры из кода в данные, чтобы расширять набор газов и тюнинговать поведение без изменения исходников.

## Поток данных (high-level)

1. Загрузка конфигов на старте.
2. Инициализация ресурсов приложения и мира.
3. Цикл фиксированного шага симуляции.
4. Обновление состояния газа/мира.
5. Синхронизация визуализации и UI.
6. Рендер кадра.

## Ограничения текущего MVP

- Мир фиксированного размера 102x102.
- Фокус разработки на подсистеме газов и базовом редакторе.
- Подсистемы жидкостей, биологии и расширенных материалов находятся в стадии проектирования.
