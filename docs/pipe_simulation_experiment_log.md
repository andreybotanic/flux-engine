# Журнал экспериментов по симуляции труб

## 2026-05-07

- Наблюдение: в текущем solver поток часто замирал в первых ячейках и не доносился глубоко по длинной трубе.
- Гипотеза 1: в `in_capacity` для входа газа в соседнюю ячейку не учитывался её фактический исходящий поток в этом тике.
- Гипотеза 2: из‑за отсутствия учёта этого фактора возникает искусственный bottleneck и «картина» 1–0–1/1–0–1 по ячейкам.
- План: вернуть API совместимости (`build_pressure_component_profile`, `build_pressure_world_exchange_requests`, `build_pressure_world_to_pipe_requests_after_outgoing`) и заменить планировщик pipe->pipe на итеративный fixed-point с учётом `start -> out -> free_in`.
- Критерий успеха: 10000 входного тика должны прокладывать фронт дальше десятков клеток без изменения логики на уровне GPU и с сохранением one-edge-per-tick.
