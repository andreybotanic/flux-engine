# Roadmap: runtime-плагины FluxEngine

Этот документ задаёт порядок работ по миграции FluxEngine на runtime-плагины.

## Цель

Перевести игру на систему плагинов так, чтобы внутренняя логика, контент и UI-расширения регистрировались через единые контракты ядра.

Целевой плагин - это пакет с:
- `manifest.toml`;
- DLL с кодом плагина;
- конфигами;
- ассетами.

Для разработки должен поддерживаться expanded dev-каталог без обязательной упаковки архива после каждого изменения.

## Жёсткие ограничения

- Приложение должно оставаться полностью функциональным после каждого этапа.
- Default plugin всегда включён, виден в списке плагинов и не может быть отключён.
- Hot reload и переключение плагинов разрешены только в главном меню, когда мир не загружен.
- Перед загрузкой мира нужно проверять только реально использованный world content. Отсутствие non-content плагина не должно блокировать загрузку.
- Существующие сейвы не мигрировать. После перехода на plugin save schema старые сейвы должны явно отклоняться.
- Физика газа остаётся в ядре. CPU-реализация остаётся эталоном, WGSL должен быть прямым переносом CPU-алгоритма.

## Как выполнять этапы

Каждый этап нужно начинать с блока "Проверка предпосылок" в соответствующем файле. Если предпосылка не выполнена, этап не начинать.

В каждом этапе есть блок "Заметка для заказчика". Это ручная проверка, которую заказчик сможет выполнить сам после реализации этапа: запустить игру, открыть нужный экран или создать мир и увидеть явный результат. Если этап технический и сам по себе не меняет gameplay, будущий исполнитель всё равно должен добавить безопасную видимую диагностику, чтобы этап можно было принять не только по тестам и логам.

После реализации каждого этапа:
- обновить `docs/technical_overview.md`, если изменились архитектура или внутренние контракты;
- обновить `docs/game_overview.md`, если изменилась пользовательская механика;
- обновить `docs/CHANGELOG.md` кратко и по существу;
- обновить `docs/project_structure.md`, если добавлены, удалены, переименованы файлы или изменилась их роль;
- запускать только связанные тесты;
- выполнить `cargo build --release`;
- запустить release-версию, проверить логи и закрыть приложение.

Если `cargo` не найден в `PATH`, использовать `C:\Users\andreybotanic\.cargo\bin\cargo.exe`.

## Критерии готовности всей миграции

- Все текущие игровые механики работают через default plugin без изменения поведения.
- В главном меню есть экран `Plugins` со списком плагинов и переключателями `On/Off`.
- Default plugin нельзя отключить.
- Plugin content регистрируется через единые IDs и registry-контракты.
- Мир не загружается, если в нём есть content из выключенного или отсутствующего content-плагина.
- Мир загружается, если отсутствует только non-content плагин.
- Плагины можно собирать и упаковывать через `xtask`.
- В dev mode можно использовать expanded plugin directory без пересборки архива.
- Hot reload работает только без загруженного мира и не оставляет приложение в частично обновлённом состоянии.
