# Changelog

## 2026-05-16
- Исправлено позиционирование `Gas Pump` в `F3` graph-overlay: multi-cell структуры теперь центрируются по `descriptor.local_bounds()` и используют тот же state-based sprite transform, что и основной world-render, поэтому насос больше не смещается на полклетки.
- Перерисованы `gas_pump` и `gas_pump_silhouette`: фланцы выровнены по центрам двух клеток (`2x1`), видимая длина насоса укладывается в центральную «одну клетку» внутри общего footprint, а корпус сделан заметно толще по высоте (почти на всю клетку).
- В панели вариантов строительства убрано принудительное `1:1` для газовых структур: иконки теперь сохраняют aspect ratio по `size_in_cells`, поэтому мост и насос больше не выглядят сжатыми.
- В default plugin добавлена новая структура `Gas Pump` (`2x1`, поворот `0/90/180/270`): входной порт `gas_in`, выходной порт `gas_out`, отдельные world-спрайты `gas_pump`/`gas_pump_silhouette` и поддержка выбора/поворота в editor `Gases`.
- Pipe runtime расширен pump-портами (`Vent` / `PumpIn` / `PumpOut`): для `PumpIn` используется конфиг `pump_input_pressure_pa`, для `PumpOut` — принудительное максимальное pipe-давление; между портами насоса отключено внутреннее pipe-ребро, а перенос `PumpIn -> PumpOut` планируется в общем hop-конвейере и коммитится на следующем hop с ограничением по `room_left` выходной трубы.
- Добавлены регрессионные тесты насоса: направления `vent -> pump_in` и `pump_out -> vent` при разных давлениях вентиляции, блокировка при отсутствии/заполнении выхода, отсутствие внутреннего pipe-ребра между портами и проверка отсутствия «внутреннего буфера» насоса.
- Введена типизированная модель категорий сущностей (`EntityCategoryDescriptor`, `EntityCategoryRef`) и двухфазная глобальная регистрация контента: сначала категории всех enabled plugins, затем их контент.
- Порядок bootstrap регистрации плагинов изменён: category id теперь глобально уникальны, конфликт id приводит к fail bootstrap с диагностикой, а ссылки сущностей на неизвестные категории отклоняются.
- ABI/SDK обновлены до версии `v7`: `FluxEntityDescriptor` получил `default_state + states[]`, `PackedState` передаётся как raw `u16`, обновлены engine/plugin manifests.
- Основной editor-toolbar переведён на динамические категории (`Cells`, `Gases`, plugin categories) в рамках инструмента `Construct`; панели вариантов открываются по активной категории и поддерживают close/reopen поведение.
- Default plugin расширен дополнительными 20 cell-сущностями (`Brick*`/`Metal*`) с уникальными именами для проверки scroll/масштабирования category-panel.
- На main-toolbar увеличен размер иконок инструментов `Build/Gases` до `32px` при размере кнопки `48px`.
- В панели вариантов инструмента `Build` иконки материалов переведены с силуэтных превью на обычные спрайты клеток.
- Исправлен выбор world-спрайта для дополнительных `Cells`: рендер стен теперь берёт спрайт по `ContentRegistry` материалу, поэтому `Metal*` больше не отображаются как `Brick`; предпросмотр силуэта под курсором синхронизирован с material-family.
- Введены core role-теги контента (`flux.core.tag.*`) для cell/structure ролей (`boundary`, `pipe`, `vent`, `pipe_bridge`, `gas_source`, `gas_sink`); `ContentRegistry` получил lookup по тегу (`cell_by_tag`, `structure_by_tag`), а world/editor-рендер начал использовать зарегистрированные дескрипторы вместо прямого выбора `metal/brick` по hardcoded id.
- `PlacedStructure` переведён на `entity + PackedState(u16)`: pipe-структуры хранят mask-state `0..15`, bridge хранит orientation-state `0/1`; state сериализуется в save chunk.
- Удалён дублирующий legacy world-render для `pipe/vent/bridge`: world-спрайт теперь рисуется одним общим путём `state -> sprite(+transform)` без второй спец-ветки.
- Save schema повышена до `7`, `placed_structures` chunk повышен до `v3`; старые сейвы без `PackedState` считаются несовместимыми и не мигрируются.
- Исправлен трекинг world-визуалов структур: `GasStructureEntities` теперь индексируется по `PlacedStructureId`, поэтому при совпадении origin (например, `pipe + vent` в одной клетке) старые спрайты не «осиротевают», не дублируются и корректно удаляются вместе со структурой.
- Исправлено чтение списка сейвов: повреждённый или частично записанный `meta.toml` в одном слоте больше не ломает весь список, такие слоты пропускаются, а валидные продолжают отображаться.
- Исправлено удаление моста/вентиляции поверх труб: удаление не затрагивает `pipe_cuts` (разрывы `Scissors`) для обычных труб, поэтому состояние соседних труб больше не меняется «случайно».
- Обновлён HUD инспектора клетки: из блока `Cell` убрана строка `State`, а для твёрдых материалов (`Brick`/`Metal`) показываются отдельные entity-блоки с названием материала.
- Исправлена передача title-only HUD-блоков из plugin SDK в host runtime: блоки с пустым `lines` теперь не теряются, поэтому `Brick/Metal` корректно отображаются отдельными блоками при наведении.
- Исправлены подписи дополнительных материалов в HUD: `Brick Alpha..Kappa` / `Metal Alpha..Kappa` теперь показывают свои реальные имена, а не общий label семейства `Brick/Metal`.
- Удалены временные тестовые `Brick*`/`Metal*` сущности из default plugin: в категории `Cells` снова остаются только базовые материалы `Brick` и `Metal`.

- Полностью переработан основной toolbar editor: оставлены только `Build/Gases`, увеличены размеры кнопок/иконок (`+20%`), удвоен межкнопочный gap и убран фон панели (видны только кнопки).
- Хоткеи инструментов изменены: `Erase` теперь переключается по `X`, `Scissors` — по `C`; добавлены unit-тесты на новый hotkey/toggle-контракт.
- Вложенные выборы `Build` и `Gases` переведены с raw-нод на полноценные `PanelManager`-панели (`BottomLeft`, header `X`, auto half-screen scroll, таблица 3 колонки) с режимом «закрыто до повторного выбора инструмента».
- Перегенерированы core-иконки инструментов `tool_build` и `tool_gases` как отдельные `256x256` PNG с прозрачным фоном; обновлены runtime `.ktx2` через `cargo generate-sprite-ktx`.
- `docs/technical_overview.md` преобразован в компактный обзор+индекс, а подробности разнесены по тематическим файлам в `docs/technical_overview/` (`01..07`) для удобной навигации и поддержки.
- Обновлён контракт intake для pipe-вентиляций: `world -> pipe` больше не зависит от `P_pipe`; расчёт выполняется только по внешним давлениям вентиляций connected-сети через signed-offer `offer_i = Σ_j (P_j - P_i)`.
- Направление сегментов на intake-этапе переведено на offer-маршрутизацию `source (offer<0) -> sink (offer>0)` с детерминированными кратчайшими путями; это устраняет ложное всасывание нейтральных вентиляций в разветвлённых сетях.
- Добавлен pipe-регресс `intake_offer_uses_only_external_vent_pressures_on_three_vent_branch`: проверяет сценарий из T-образной сети (`100/0/50 Pa`), где intake идёт только через вентиляцию с отрицательным offer и нижняя нейтральная ветка не запускает поток.
- Уточнено деление intake: `n` теперь считается как число исходящих запросов из вентиляции в текущем hop (входящие запросы в `n` не включаются); добавлен регресс `intake_split_uses_outgoing_requests_not_sink_count`.
- Intake-функция возвращена к базовой линейной модели от приведённой дельты давления `x_pa = abs(offer)/n_outgoing_requests` с явным переводом в частицы: `x_particles = x_pa / cell_particle_pressure_pa`, затем `request = round(x_particles/25)` с ограничением `<= 200000` частиц (и дополнительным respect к `max_vent_flux_particles_per_tick`).
- Добавлено правило минимального intake: при `x_particles >= 5` вентиляция обязана втянуть хотя бы `1` частицу, даже если линейное округление дало `0`.
- Обновлены pipe-регрессы под линейный контракт: `low_pressure_offer_uses_linear_intake_mapping`, `linear_intake_curve_matches_baseline_rules` и `delta_30_single_outgoing_path_intake_is_at_least_one`.
- Обновлён базовый масштаб давления/частиц: `cell_particle_pressure_pa` в pipe-runtime переключён с `1.0` на `0.2`, что даёт `1 Pa = 5` частиц в world и `1` частица `= 5 Pa` в pipe (при `cell_volume_ratio = 25`).
- Обновлён debug HUD-блок `[DEBUG] Pipe/Vent`: добавлены поля external offer (`of`), число путей (`n`) и offer-based request (`rq`) для пошаговой диагностики intake-гейтов.

## 2026-05-14
- Pipe runtime переписан на детерминированную конвейерную модель (`offer -> demand -> match -> commit`) с hop-каденсом `pipe_step_interval_ticks` (по умолчанию `10`) и отдельным backpressure-правилом остановки тупиковых веток.
- В `PipeSimulationConfig` и `pipe_runtime.toml` удалены поля старого flux-solver (`pipe_flux_gain`, `pipe_flux_damping`, `max_pipe_flux_particles_per_tick`) и добавлены `pipe_step_interval_ticks`, `max_pipe_hop_particles_per_step`, `min_pipe_branch_residual_particles`.
- Вентиляции теперь блокируют intake в ветки без downstream outlet; логика `pipe -> world` / `world -> pipe` сохранена в фиксированном порядке после hop-переносов.
- Добавлены новые pipe-тесты на blocked-ветки, рекурсивный backpressure, восстановление потока после разблокировки и параметризованный multi-vent stress для `100 Pa`, `1 kPa`, `1 MPa` (smoke + full).
- Добавлен отдельный regression-тест `room_to_empty_room_pipe_front_fills_without_hop_gaps`: проверяет, что при переносе из газовой комнаты в пустую фронт по трубе растёт на каждом hop без пропусков (`11/21/31...`).
- Исправлена детерминированная потеря подпитки на отдельных hop-тиках (`~21/41/...`) в сценариях `room -> pipe -> empty room`: source-вент теперь делает make-up intake при исходящем conveyor-потоке и не сбрасывает газ обратно в world в этот же режим.
- Добавлена регрессия на непрерывность source-edge transfer-ов по hop-ам для pressure-tier `100 Pa / 1 kPa / 1 MPa`: после старта фронта `pipe -> pipe` перенос от входной вентиляции не должен «пропадать через hop».
- В `F3` визуал pipe-содержимого унифицирован: движущийся перенос рендерится тем же типом контейнера, что и газ в трубе, с плавной фазой внутри hop-интервала и сохранением bridge-дуг.
- Для `F3` убрано визуальное дублирование static/payload: stationary слой теперь вычитает incoming hop-массу, переносимая масса показывается только движущимся контейнером, а `flow_progress` внутри интервала `N=10` идёт равномерными шагами `1/10` (до `0.9` на последнем non-hop-тике) с полным переходом на hop-тике без «пропуска кадра».
- Убраны неиспользуемые helper-функции и test-only утилиты переведены под `#[cfg(test)]`, чтобы релизная сборка не засыпалась `dead_code`-warning'ами.
- По обратной связи визуал `F3` упрощён до только moving-контейнеров (без отдельного стационарного квадрата), а `pipe -> pipe` получил сегментное конвейерное ограничение: внутри сегмента между вентиляцией/развилкой в одном hop разрешено только одно направление потока, при этом на самих развилках split по нескольким сегментам сохранён.
- Зафиксирован единый `F3`-режим для paused/running: пауза больше не переключает трубы на отдельный статичный слой, текущая фаза moving-контейнеров просто замораживается и остаётся видимой «между трубами».
- Исправлена потеря видимости intake на первом hop: vent-переносы `world -> pipe`/`pipe -> world` теперь также пишутся в `PipeFlowVisualState.transfers`, а новый регрессионный тест `first_hop_vent_intake_is_visible_in_flow_transfers` проверяет, что при ненулевой массе во входном сегменте `F3` не остаётся пустым.
- Для vent-переносов в `F3` добавлен направленный visual-path в соседний pipe-сегмент: intake-пакет больше не «стоит в клетке», а движется к соседней трубе по той же фазе `0.0..1.0`; добавлен overlay-регресс `vent_intake_packet_moves_toward_neighbor_cell_over_interval`.
- Исправлен архитектурный разрыв визуализации на границе hop-ов: `PipeFlowVisualState` теперь ведёт `previous_transfers + transfers`, и на тик старта нового hop `F3` показывает завершённую позицию прошлого hop вместо мгновенного исчезновения; добавлен регрессионный тест `hop_boundary_render_uses_previous_hop_endpoint`.
- Уточнён контракт вентиляции: direct-обмен с миром теперь строго локальный по vent-клетке (без забора/выброса сразу из всей connected room); добавлены регрессионные тесты `vent_intake_reads_only_its_own_world_cell` и `vent_output_writes_only_its_own_world_cell`.
- Vent-логика на hop-тике переведена на явный pipeline с буфером (`pipe -> vent_buffer -> world`, intake между этими фазами): vent-сегмент сначала дренируется в buffer, затем выполняется `world -> pipe` intake только для forward-demand vent-узлов, после чего buffer выпускается в world-клетку вентиляции.
- Добавлен регрессионный тест `sink_vent_drains_arrived_hop_mass_before_world_release`, который фиксирует дренаж vent-сегмента на hop-е прихода массы и release в локальную world-клетку.
- Пересчёт pipe-направлений на intake-этапе теперь выполняется на каждом hop заново для всех сегментов; для сегментов `vent <-> vent` направление приоритетно определяется по разности внешних давлений на вентиляциях, что убирает эффект «насоса» после смены градиента.
- Если ventilation по новому направлению должна всасывать, но в этом hop занята выпуском buffer, то весь соответствующий сегмент останавливается на текущий hop (direction reset).
- Добавлен регрессионный тест `intake_stage_recomputes_segment_direction_when_room_pressures_flip`, который проверяет разворот направления после смены давления между двумя комнатами.
- В HUD добавлен отдельный блок `[DEBUG] Pipe/Vent` для клеток труб/вентиляций: в нём выводятся intake-gate условия текущего hop (`forward_demand`, `has_outlet`, `buffered`, `pressure/conveyor request`, `room_left`) и диагностические причины блокировки.
- Исправлено дрожание/ложный разворот направления внутри одного hop-интервала: планирование `pipe -> pipe` теперь использует зафиксированное на intake-этапе направление сегмента и не пересчитывает его повторно после `vent_buffer -> world` release в том же hop.
- Добавлен regression-тест `segment_does_not_plan_reverse_while_external_gradient_sign_is_stable`: пока знак внешнего градиента на вентиляциях не меняется, source-edge не может получить обратный `plan`.
- Debug-блок `[DEBUG] Pipe/Vent` переведён в компактный формат строк (`ph/seg/e/tr/v/i`), чтобы помещаться на экран при пошаговой отладке.
- В `F3` восстановлена видимость газа в заблокированных pipe-ветках: если у узла нет активного transfer в текущем hop, но масса в узле есть, рендерится удерживаемый контейнер в центре узла тем же стилем пакета.
- Добавлен overlay-регресс `stationary_pipe_mass_without_transfers_still_renders_packet`, который фиксирует отображение массы трубы без активных transfer-ов.
- Пересобран blocked-neighbor шаг дискретного газа в CPU (`src/simulation/discrete_step_step_block.rs`) и WGSL (`assets/shaders/gas_solver.wgsl`) по единому reflective-правилу: закрытое направление получает вес `0`, а его mobility-доля добавляется в `stay`; удалены special-case ветки перераспределения вдоль стен/углов, чтобы убрать algorithm drift между backend-ами.
- Добавлены wall-bias сценарии (`open_room`, `center_block`, `stair_step`) с плотностями `100/1000/10000` и прогоном `~1000` шагов в CPU/GPU тестах; концентрационный критерий `near_wall_avg / far_avg >= 0.97` закреплён как регрессия, для импульсов добавлена радиальная околостенная метрика.
- Установлен `cargo-wgsl`; WGSL-валидация вынесена в отдельный лёгкий crate `xtask_wgsl`, а alias `cargo validate-wgsl` теперь запускает именно его (без сборки `flux_engine`). Команда валидирует все `*.wgsl` по репозиторию, печатает цветной список файлов с пометками `CHANGED/UNCHANGED` и `OK/NOT OK`, выводит диагностические ошибки для проблемных файлов и итоговую сводку `total/changed/ok/errors`; `cargo xtask build-release` перед сборкой запускает тот же шаг через `cargo validate-wgsl`; для bevy-шейдеров с `#import` используется `naga_oil` fallback.
- `collapsible_block` переведён на кликабельный заголовок: сворачивание/разворачивание теперь срабатывает по клику в любую точку header-строки, а состояние показывается той же `select_arrow`-иконкой, что и в dropdown `select` (через `flip_y`).
- Кнопка сворачивания обычных panel-header тоже переведена с `+/-` на ту же `select_arrow`-иконку внутри кнопки; направление иконки синхронизируется по `collapsed` через `flip_y`.
- У content-части `collapsible_block` убрана верхняя граница рамки: рамка оставлена только по бокам и снизу, чтобы header и content визуально не разделялись двойной линией.
- Для `toggle_switch` добавлен compact-layout в варианте без label: высота switch и внутренних элементов уменьшена, чтобы строки `Buoyancy/Show impulses` визуально совпадали по вертикальному ритму с input-строками.
- Для panel viewport при активном скролле добавлен резерв ширины под scrollbar (`padding-right` увеличивается на ширину скроллбара), поэтому полоса прокрутки больше не перекрывает правый контент-отступ.
